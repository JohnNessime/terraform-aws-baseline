# `bootstrap`

Creates the remote-state backend — an encrypted S3 bucket and a DynamoDB lock
table — that every other root module uses. It runs **once**, with local state,
and then hands its own state over to the bucket it just built.

Full walkthrough of the migration: [`docs/bootstrap.md`](../docs/bootstrap.md).

## What it creates

- **S3 state bucket** — versioning on, SSE-KMS with a customer-managed key,
  all four public-access-block flags, a TLS-only bucket policy (`aws:SecureTransport
  = false` → Deny), server access logging to a separate log bucket, and a
  lifecycle rule expiring noncurrent versions after 90 days.
- **S3 log bucket** — the access-log sink for the state bucket, itself
  encrypted, versioned, and locked down.
- **DynamoDB lock table** — `LockID` hash key, `PAY_PER_REQUEST`, point-in-time
  recovery, and SSE with the customer-managed key.
- **KMS key** — rotation enabled, with a key policy that grants the account root
  administration and lets S3 log delivery encrypt access logs.

## Run it once

```bash
cd bootstrap
terraform init            # local state
terraform apply

# then migrate state into the bucket you just created:
#   copy the outputs into environments/*/backend.tf and run
#   terraform init -migrate-state
```

The outputs (`state_bucket_name`, `lock_table_name`, `kms_key_arn`, `region`)
are exactly the values each environment's `backend.tf` needs.
