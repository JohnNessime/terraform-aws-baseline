# `iam` module

Three roles that between them remove every long-lived credential from the
account: no AWS keys in CI, no standing human access, no SSH keys on hosts.

## 1. GitHub Actions OIDC role — the centrepiece

GitHub Actions authenticates to AWS with a short-lived OIDC token instead of a
stored access key. The security of the whole arrangement lives in one line of
the trust policy — the `sub` condition:

```
repo:<org>/<repo>:ref:refs/heads/<branch>
```

matched with **`StringEquals`, never `StringLike`**. A wildcard turns the role
into an open door:

| `sub` value | Who can assume the role |
|-------------|-------------------------|
| `repo:acme/baseline:ref:refs/heads/main` | only `main` of that one repo ✅ |
| `repo:acme/*` | every repo in the org |
| `repo:*` | **any repo on GitHub, owned by anyone** |

With a wildcard, an attacker just pushes a workflow to a matching repo and
inherits these AWS permissions. The exact-match `sub` is the trust boundary.

The role's only standing permission from this module is scoped remote-state
access (S3 + DynamoDB lock + KMS decrypt), and only when you pass those ARNs.
Deploy permissions for whatever the pipeline manages are layered on by the
caller — deliberately not granted here.

## 2. Auditor role — read-only, MFA-gated

Assumable only by the principals you pass in `auditor_principal_arns`, and only
when `aws:MultiFactorAuthPresent` is true. It carries the AWS-managed
`SecurityAudit` and `ViewOnlyAccess` policies — enough to inspect everything,
enough to change nothing. Read-only is still read-of-everything, so it is not
handed out on a bare long-lived credential.

## 3. EC2 instance role — SSM instead of SSH

One managed policy, `AmazonSSMManagedInstanceCore`, and nothing else. That
enables Session Manager, which replaces SSH outright: no inbound port 22, no key
pairs to rotate or leak, no bastion host to run and patch. Every session is
IAM-authorised and logged.

## Notes

- The OIDC provider is account-global. Create it in the first environment
  (`create_github_oidc_provider = true`) and reference it from the rest
  (`= false`) — an account rejects a second provider for the same URL.
- All policies are generated from `aws_iam_policy_document`, so `terraform plan`
  shows a readable diff and there are no stringly-typed JSON heredocs to drift.
